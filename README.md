# Options Pricing & Volatility Engine

Black-Scholes-Merton pricing and Greeks, implied-volatility inversion, an SVI
volatility surface with no-arbitrage checks, Monte Carlo with variance reduction,
and GARCH / GJR-GARCH written from scratch by maximum likelihood.

Every component is validated against something that must be true — a
no-arbitrage identity, an independent computation, a theoretical variance
reduction, or parameter recovery from simulated data.

**New to options?** Read [`docs/CONCEPTS.md`](docs/CONCEPTS.md) first. It starts
from "what is a call option" and ends at the variance risk premium, assuming no
prior knowledge. [`docs/INTERVIEW.md`](docs/INTERVIEW.md) is the same material in
Q&A form.

## Quick start

Needs Python 3.9+, numpy, scipy, matplotlib. Nothing else is required —
`statsmodels`, `arch` and `yfinance` are all optional.

```bash
cd options-vol-engine
pip install numpy scipy matplotlib

python tests/test_all.py                     # 263 validation checks
python scripts/run_all.py                    # everything, ~2 minutes
```

Or one at a time:

```bash
python scripts/01_pricing_greeks_iv.py       # pricing, Greeks, IV inversion
python scripts/02_volatility_surface.py      # SVI fit + arbitrage checks
python scripts/03_monte_carlo.py             # convergence + variance reduction
python scripts/04_garch_forecasting.py       # GARCH, GJR, out-of-sample study
```

Every script prints a full narrated explanation alongside its numbers, so the
output is readable on its own.

### With live market data

```bash
pip install yfinance
python scripts/02_volatility_surface.py --ticker SPY
python scripts/04_garch_forecasting.py --ticker SPY
```

Both fall back to bundled/synthetic data if `yfinance` or the network is
unavailable, so nothing breaks.

### The real-data calibration in `results/RESULTS.md`

That result set (SPY/AAPL/TSLA, validation numbers, calibration RMSE,
economic interpretation of the skew) is reproducible offline from the
frozen chains already in `data/chains/`:

```bash
python scripts/00_validate_pricer.py                          # results/validation_report.json
python scripts/05_real_chain_calibration.py --ticker SPY      # results/vol_surface_SPY.json + 3 PNGs
python scripts/05_real_chain_calibration.py --ticker AAPL
python scripts/05_real_chain_calibration.py --ticker TSLA
```

To pull a fresh snapshot instead of using the frozen one:
`python scripts/fetch_real_chains.py --ticker SPY` (needs `yfinance` and
network; see `docs/CONCEPTS.md` §12b for why the expiries it picks span a
full year rather than just the nearest few listed).

## Why the default data is synthetic (and why that is a strength)

With real market data you can fit a surface but you can never check it, because
the true volatility surface is not an observable object.

The synthetic chain is generated from a **known SVI surface**, so the pipeline
can be scored against the truth. It deliberately includes everything that makes
real chains hard:

- bid-ask spreads that widen in the wings and for short maturities
- prices rounded to the real US tick grid ($0.01 below $3, $0.05 above)
- deep wings quoting at the minimum tick, which destroys their implied vol
- thin volume and open interest out of the money
- a handful of genuinely stale and crossed quotes

Same logic for GARCH: `simulate_garch` generates returns from known parameters so
the estimator can be asked to recover them. **An estimator that cannot recover
parameters from data generated by its own model is telling you nothing when you
point it at the market.**

Real-data loaders (`load_yfinance_chain`, `load_yfinance_returns`) are included
and documented, with the caveats real data brings — unsynchronised quotes,
assumed rather than observed rates and dividends, American exercise.

## What makes the tests worth having

They are not "does the function return a number". They are **identities** and
**recovery tests** — statements that must hold exactly, or estimators asked to
recover parameters from data generated with those very parameters:

- put-call parity to machine precision (pure no-arbitrage, model-free)
- analytic Greeks against an independent finite-difference computation
- implied vol inverting Black-Scholes exactly, round trip
- Monte Carlo landing within 4 standard errors of the closed form
- variance reduction matching `1/(1 - rho^2)`, not just "getting smaller"
- the vectorised GARCH recursion bit-identical to the naive loop
- the GARCH MLE recovering known parameters, with z-scores
- GJR finding a leverage effect when there is one and **not** when there isn't
- SVI recovering the surface that generated the chain
- the arbitrage checkers correctly **rejecting** a deliberately broken smile

## Known limitations

- **European exercise only.** US equity options are American. The OTM-only
  convention keeps the early-exercise premium small, but it is not zero,
  especially for in-the-money puts.
- **`r` is assumed, `q` is extracted -- and that split is deliberate.** On a
  real SPY/AAPL/TSLA calibration (`results/RESULTS.md`), fitting both from
  put-call parity per expiry made the extracted `r` swing from -23% to +21%
  between adjacent weekly expiries: short-dated quotes don't carry enough
  interest-rate signal to identify `r` on their own. `r` is now fixed at a
  known external rate; `q` (which mixes dividends with, for single names,
  stock-borrow cost) is the genuinely uncertain quantity extracted per
  expiry. See `docs/CONCEPTS.md` §12b.
- **No stochastic volatility model.** SVI describes the surface; it does not
  explain it. Heston or SABR would be the natural next step.
- **The squared-return proxy is noisy.** Realised variance from intraday data
  would give a much sharper forecast comparison, and a HAR-RV model usually beats
  GARCH when you have that data.
- **No transaction costs in any P&L statement**, because none is claimed. There
  is no trading strategy here, only pricing and forecasting.
